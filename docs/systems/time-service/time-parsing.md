# 时间解析规则

> 本文档详细说明时间服务的时间解析能力，包括支持的格式、解析优先级和实现细节。

## 1. 概述

当时间模式设置为 `simulated` 时，TimeService 会尝试从传入的文本内容中提取时间信息。这个功能主要用于：

- 从角色扮演消息中同步剧情时间
- 支持中文、英文、数字混合的时间表述
- 智能处理模糊时间（如"下午3点"）

## 2. 支持的格式

### 2.1 完整日期时间（最高优先级）

同时包含日期和时间的格式，解析成功后直接返回完整的 Date 对象。

| 格式 | 示例 | 解析结果 |
|------|------|----------|
| 中文完整 | `2028年6月5日 09:30` | 2028-06-05 09:30 |
| 带星期 | `2028年6月5日 星期一 09:30` | 2028-06-05 09:30 |
| 短横线分隔 | `2024-05-01 12:00` | 2024-05-01 12:00 |
| 斜杠分隔 | `2024/06/05 14:30` | 2024-06-05 14:30 |

**正则表达式**：

```javascript
/(\d{4})[年\/\-\.]\s?(\d{1,2})[月\/\-\.]\s?(\d{1,2})[日号]?\s+(?:星期[一二三四五六日]\s+)?(\d{1,2})[:：](\d{1,2})/
```

### 2.2 仅日期（数字格式）

只包含日期，不包含时间。解析后保持当前时间的时分秒不变。

| 格式 | 示例 | 说明 |
|------|------|------|
| 中文年月日 | `2024年5月1日` | 支持1-2位月日 |
| 短横线 | `2024-06-05` | ISO 格式 |
| 斜杠 | `2024/06/05` | 常见格式 |
| 点号 | `2024.06.05` | 欧洲格式 |

**正则表达式**：

```javascript
/(\d{4})[年\/\-\.]\s?(\d{1,2})[月\/\-\.]\s?(\d{1,2})[日号]?/
```

### 2.3 中文日期

纯中文数字表示的日期。

| 格式 | 示例 | 解析结果 |
|------|------|----------|
| 完整年月日 | `二零二四年五月一日` | 2024-05-01 |
| 混合格式 | `二零二四年5月1日` | 2024-05-01 |

**正则表达式**：

```javascript
/([零一二三四五六七八九十]{2,4})年([零一二三四五六七八九十]{1,2})月([零一二三四五六七八九十]{1,3})日/
```

**中文数字转换**：

```typescript
function cnToInt(str: string): number {
  const map: Record<string, number> = {
    '零': 0, '一': 1, '二': 2, '三': 3, '四': 4,
    '五': 5, '六': 6, '七': 7, '八': 8, '九': 9,
    '十': 10, '两': 2
  }
  
  // 年份处理："二零二四" -> 2024
  if (str.length === 4 && (str.includes('二') || str.includes('零'))) {
    return parseInt(str.split('').map(c => map[c]).join(''))
  }
  
  // 处理 1-99 的数字
  // "十二" -> 12, "二十" -> 20, "二十三" -> 23
  // ...
}
```

### 2.4 数字时间

标准的时:分格式。

| 格式 | 示例 | 解析结果 |
|------|------|----------|
| 24小时制 | `09:30` | 09:30 |
| 24小时制 | `14:30` | 14:30 |
| 中文冒号 | `09：30` | 09:30 |
| 单位数小时 | `9:30` | 09:30 |

**正则表达式**：

```javascript
/\b([0-1]?[0-9]|2[0-3])[:：]([0-5][0-9])\b/
```

### 2.5 中文模糊时间（重点功能）

支持自然语言的时间表述，是角色扮演场景的核心需求。

| 表述 | 解析结果 | 说明 |
|------|----------|------|
| `上午九点` | 09:00 | |
| `下午3点` | 15:00 | 自动 +12 |
| `下午3点半` | 15:30 | "半" -> 30分 |
| `晚上八点` | 20:00 | |
| `凌晨12点` | 00:00 | 特殊处理 |
| `中午12点` | 12:00 | |
| `下午两点` | 14:00 | "两" = 2 |
| `上午十一点二十分` | 11:20 | |

**时段映射**：

| 时段词 | 小时调整规则 |
|--------|-------------|
| `凌晨` | 12点 → 0点，其他不变 |
| `早上` | 不调整 |
| `上午` | 不调整 |
| `中午` | 不调整 |
| `下午` | 小于12时 +12 |
| `晚上` | 小于12时 +12 |

**正则表达式**：

```javascript
/(凌晨|早上|上午|中午|下午|晚上)?\s?([零一二三四五六七八九十两\d]{1,2})点(半|[零一二三四五六七八九十\d]{1,2}分?)?/
```

### 2.6 英文日期（回退）

作为回退方案，支持部分英文日期格式。

| 格式 | 示例 | 解析结果 |
|------|------|----------|
| 月日年 | `June 5, 2028` | 2028-06-05 |
| 斜杠格式 | `2028/06/05` | 2028-06-05 |

**正则表达式**：

```javascript
/(\d{4}\/\d{1,2}\/\d{1,2})|([A-Z][a-z]{2,8}\s+\d{1,2},?\s+\d{4})/
```

## 3. 解析优先级

解析器按以下顺序尝试匹配，首次成返回：

```text
┌─────────────────────────────────────────────────────────────┐
│  1. 完整日期时间（数字）                                      │
│     "2028年6月5日 09:30"                                     │
│     ↓ 失败                                                   │
├─────────────────────────────────────────────────────────────┤
│  2. 仅日期（数字）+ 仅时间（数字）                            │
│     "2028年6月5日" + "09:30"                                 │
│     ↓ 失败                                                   │
├─────────────────────────────────────────────────────────────┤
│  3. 中文日期                                │
│     "二零二四年五月一日"                                      │
│     ↓ 失败                                                   │
├─────────────────────────────────────────────────────────────┤
│  4. 数字时间（独立）                                          │
│     "09:30"                                                  │
│     ↓ 失败                                                   │
├─────────────────────────────────────────────────────────────┤
│  5. 中文模糊时间                                              │
│     "下午3点半"                                               │
│     ↓ 失败                                                   │
├─────────────────────────────────────────────────────────────┤
│  6. 英文日期（回退）                                          │
│     "June 5, 2028"                                           │
│     ↓ 失败                                                   │
├─────────────────────────────────────────────────────────────┤
│  返回 null（未找到时间信息）                                  │
└─────────────────────────────────────────────────────────────┘
```

## 4. 解析逻辑详解

### 4.1 基准日期

解析时使用当前虚拟时间作为基准日期：

```typescript
private parseContentToDate(content: string, baseDate: Date): Date | null {
  let resultDate = new Date(baseDate)  // 复制基准日期
  let matched = false
  
  // 各式的匹配...
  
  return matched ? resultDate : null
}
```

**为什么需要基准日期**：

- 仅匹配到时间时（如 "下午3点"），需要保留原来的日期部分
- 仅匹配到日期时，需要保留原来的时间部分

### 4.2 组合匹配

当同时匹配到日期和时间时，会组合成完整结果：

```typescript
// 先匹配日期
if (dateMatch) {
  resultDate.setFullYear(...)  
  resultDate.setMonth(...)
  resultDate.setDate(...)
  matched = true
}

// 再匹配时间
if (timeMatch) {
  resultDate.setHours(...)
  resultDate.setMinutes(...)
  resultDate.setSeconds(0)
  
  // 如果之前匹配了日期，返回组合结果
  if (matched) {
    return resultDate
  }
  
  // 仅有时间，也返回
  return resultDate
}
```

### 4.3 调试日志

开发模式下会输出详细的解析日志：

```typescript
const shouldLog = import.meta.env.DEV

if (shouldLog) {
  console.groupCollapsed('[TimeService] Parsing Message Content')
  console.log('Original Content:', content.substring(0, 50))
  // 匹配过程...
  console.log('Result:', resultDate.toLocaleString())
  console.groupEnd()
}
```

**示例输出**：

```text

  Original Content: 现在是2028年6月5日 下午3点，我们...

```

## 5. 实际应用场景

### 5.1 角色扮演消息

```text
角色消息：
"【2028年6月5日 星期一 早上9:30】
阳光透过窗帘洒进房间，你睁开了眼睛..."

→ 解析结果：2028-06-05 09:30:00
```

### 5.2 叙事时间跳转

```text
旁白：
"时间来到了下午3点半，教室里..."

→ 解析结果：(当前日期) 15:30:00
```

### 5.3 对话中的时间提及

```text
角色对话：
"明天上午十点在咖啡厅见面吧"

→ 解析结果：(当前日期) 10:00:00
（注意："明天" 不会被处理，仅提取时间）
```

## 6. 限制与注意事项

### 6.1 当前限制

| 限制 | 说明 |
|------|------|
| 不支持相对日期 | "明天"、"下周"、"3天后" 不会被解析 |
| 不支持年份省略 | "6月5日" 不会更新年份 |
| 不支持秒 | 时间只解析到分钟级别 |
| 首次匹配 | 多个时间只取第一个匹配 |

### 6.2 最佳实践

**对于角色扮演内容创作者**：

1. 在重要时间节点使用明确的完整格式：
   ```text
   【2028年6月5日 09:30】
   ```

2. 使用中文时段词增加识别率：
   ```text
   ✓ "下午3点" → 15:00
   ✗ "3点" → 可能被识别为 03:00
   ```

3. 避免在同一消息中混用多个时间：
   ```text
   ✓ "现在是上午10点"
   ✗ "从上午10点到下午3点" → 只会取第一个
   ```

## 7. 扩展计划

### 7.1 计划中的改进

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 相对日期支持 | 中 | "明天"、"后天"、"下周一" |
| 多时间提取 | 低 | 返回所有匹配的时间 |
| 时区支持 | 低 | 处理不同时区的时间 |
| LLM 辅助解析 | 低 | 复杂表述交给 LLM |

### 7.2 自定义解析器扩展点

未来可能提供自定义解析器注册：

```typescript
// 规划中的 API
timeService.registerParser('custom', {
  pattern: /.../, 
  parse: (match) => new Date(...)
})
```
