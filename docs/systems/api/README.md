# API 文档导航

本目录用于维护“可直接调用服务”的统一 API 视图，目标是让开发和编排都能在同一套术语下完成。

## 文件说明

| 文件 | 作用 | 适用场景 |
| --- | --- | --- |
| `api-manifest.json` | 权威方法签名与服务元数据 | 查参数、查返回类型、做自动化校验 |
| `API-INDEX.md` | 18 个服务的 8 字段摘要（依赖/事件/副作用） | 快速评估改动影响面 |
| `API-RECIPES.md` | 场景化调用链路与降级策略 | 直接套用业务编排顺序 |

## 推荐阅读顺序

1. `api-manifest.json`：确认签名和状态。
2. `API-INDEX.md`：确认依赖、事件和副作用。
3. `API-RECIPES.md`：落地调用顺序与失败降级。

## 更新规则

- 服务接口发生变化时，必须同步更新以上 3 个文件。
- 仅“可直接调用服务”写入 `services[]`；设计态服务只留在说明区，不进入可调用清单。
- 稳定性只使用 `stable`、`beta`、`experimental` 三档，并保持跨文件一致。
- Recipe 中的事件名必须能在代码或服务文档中定位。

## 提交流程建议

1. 修改文档。
2. 自检链接、方法名、事件名。
3. 运行项目既有构建/校验命令，确认没有引入回归。
4. 在提交说明里标注“接口变更”或“文档对齐”。
