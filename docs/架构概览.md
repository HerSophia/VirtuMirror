**版本**: 3.0 (独立架构版)

## 1. 项目概述

手机模拟器是一个跨平台的虚拟手机应用，可以作为 SillyTavern 插件运行，也可以通过 Socket Bridge 独立运行并与多种平台连接。为角色扮演场景提供逼真的手机界面体验，用户可以通过模拟手机与AI角色进行微信聊天、查看朋友圈、浏览网页等交互。

### 1.1 核心功能

- 📱 **手机界面模拟** - 逼真的iOS风格手机外观，支持手机/平板模式切换
- 💬 **聊天应用** - 微信风格的聊天界面，支持文本、语音、图片、红包等
- 📧 **邮件** - 邮件列表和详情
- 🌐 **浏览器** - 网页浏览模拟
- 📺 **直播中心** - 直播间观看体验
- 🖼️ **图库** - 图片管理和查看
- 🎨 **多主题系统** - 预设主题 + 自定义主题编辑器
- 🔔 **通知系统** - 系统消息聚合与管理
- ⚙️ **控制中心** - 下拉快捷设置面板
- 🔄 **多任务切换** - App 切换器，支持查看和管理运行中的应用
- 🌉 **Bridge 桥接** - 支持独立运行并通过 Socket 与酒馆等平台连接
- 🏪 **应用商店** - 支持安装第三方配置式应用
- 📝 **提示词管理** - 内置提示词模板管理
- 🔊 **音频服务** - 统一的音频播放和音量控制
- ⏰ **时间服务** - 支持模拟时间与真实时间切换

**核心理念**：桌面（Home）本身就是一个 App，只是它比较特殊，是整个系统的入口。这样开发和维护方式与其他 App 保持一致。

```

├── HomeApp.vue           # 桌面主组件
├── index.ts              # 导出入口
├── types.ts              # 类型定义
├── components/           # 桌面组件

│   └── DockBar.vue       # 底部 Dock 栏

```

**与其他 App 的对比**：
| 特性 | Home App | 普通 App |
|------|----------|----------|
| 路由路径 | `/` | `/chat`, `/settings` 等 |
| 入口组件 | `HomeApp.vue` | `ChatApp.vue` |

**核心理念**：状态栏（Status Bar）也是一个特殊的 App，它不参与路由系统，但采用与其他 App 相同的架构模式来组织代码。

**设计优势**：
- **架构一致性**：所有系统级组件都遵循相同的目录结构和命名规范
- **易于维护**：相关组件（状态栏、通知中心、控制中心）集中管理
- **可扩展性**：未来可以轻松添加新的下拉面板

#### 3.2.3 过渡动画

系统支持两种过渡动画类型：**Slide（滑动）** 和 **Zoom（缩放）**。

**Slide 动画** - 用于 App 内部页面之间的导航：

```
前进导航 (slide)
┌────────┐     ┌────────┐
│ 旧页面  │ ──→ │ 新页面  │
│  ←30%  │     │  100%→ │
└────────┘     └────────┘
   z:1            z:2

后退导航 (slide-back)
┌────────┐     ┌────────┐
│ 新页面  │ ←── │ 旧页面  │
│  ←30%  │     │  →100% │
└────────┘     └────────┘
   z:1            z:2
```

**Zoom 动画** - 用于桌面与 App 之间的切换：

```
打开 App (zoom-in)
┌────────┐           ┌────────┐
│ 🔲 图标  │  ─放大→   │  App   │
│        │           │  界面   │
└────────┘           └────────┘
 scale: 0.3 → 1.0
 origin: 图标位置

关闭 App (zoom-out)
┌────────┐           ┌────────┐
│  App   │  ─缩小→   │ 🔲 图标  │
│  界面   │           │        │
└────────┘           └────────┘
 scale: 1.0 → 0.3
 origin: 图标位置
```

**动画类型自动判断**：
| 场景 | 动画类型 | 方向 |
|------|----------|------|
| 桌面 (HomeApp) → App | zoom-in | forward |
| App → 桌面 (HomeApp) | zoom-out | back |
| App 内部页面切换 | slide / slide-back | 根据历史栈判断 |
| 手势上滑返回桌面 | zoom-out | back |

#### 3.2.4 导航方向检测与手势系统

系统使用**响应式历史栈追踪**判断导航方向，并导出 `canGoBack` 计算属性供手势系统使用：

```typescript
// src/router/index.ts
export const navigationDirection = ref<'forward' | 'back'>('forward')

// 导航历史栈（响应式）
const historyStack = ref<string[]>(['/'])

// 是否可以返回（基于内部历史栈判断）
export const canGoBack = computed(() => {
  return historyStack.value.length > 1
})

router.beforeEach((to, from, next) => {
  const indexInStack = historyStack.value.indexOf(to.path)
  
  if (indexInStack !== -1 && indexInStack < historyStack.value.length - 1) {
    // 目标在栈中且不在栈顶 → 后退
    navigationDirection.value = 'back'
    historyStack.value = historyStack.value.slice(0, indexInStack + 1)
  } else if (to.path === '/' && from.path !== '/') {
    // 回到首页始终是后退
    navigationDirection.value = 'back'
    historyStack.value = ['/']
  } else {
    // 前进导航
    navigationDirection.value = 'forward'
    historyStack.value = [...historyStack.value, to.path]
  }
  next()
})
```

**方向检测逻辑**：
| 场景 | 检测方式 | 动画方向 |
|------|----------|----------|
| 目标路径在历史栈中 | 后退 | slide-back (从左往右) |
| 回到首页 (/) | 后退 | slide-back |
| 新路径（不在栈中） | 前进 | slide (从右往左) |

**导航模式对比**：
| 特性 | 手势导航 | 三键导航 |
|------|----------|----------|

| 学习成本 | 较高 | 低 |
| 操作效率 | 熟练后更快 | 稳定一致 |
| 误触风险 | 较高 | 较低 |
| 适用场景 | 追求沉浸感 | 传统 Android 用户习惯 |

**手势系统**（ViewsContainer.vue，仅手势导航模式）：
| 手势 | 触发区域 | 触发条件 | 动作 |
|------|----------|----------|------|
| 左侧向右滑动 | 屏幕左侧 1/4 | 滑动距离 > 80px 或快速滑动 | 返回上一页 |
| 右侧向左滑动 | 屏幕右侧 1/4 | 滑动距离 > 80px 或快速滑动 | 返回上一页 |
| 底部向上滑动 | 屏幕底部 60px | 速度 ≥ 0.8px/ms 或距离 > 100px | 返回桌面 |

- Zoom 动画的 `transform-origin` 动态指向对应 App 图标的位置
- 图标位置由 `appStateStore` 管理，在 HomeScreen 挂载时自动注册

**路由设计原则**：
- 路由参数（`:contactId`）替代散落的 `activeXxxId` 状态
- 支持嵌套路由（如 ChatApp > ChatConversation）
- 响应式历史栈：精确判断导航方向和返回可用性
- 分层加载：核心组件立即加载，次要组件懒加载
- 空闲预加载：利用 `requestIdleCallback` 预加载组件
- KeepAlive 缓存：避免频繁切换时重复渲染
- 动态过渡类型：自动选择 zoom 或 slide 动画

## 4. 核心机制

### 4.1 UI 加载机制

**重要**: 插件 UI 采用自管理加载方式，不依赖 SillyTavern 的 `renderExtensionTemplateAsync()`。

```typescript
// plugin-entry.ts
async function initializePlugin() {
  // 使用 import.meta.url 计算当前脚本路径
  const scriptUrl = new URL(import.meta.url);
  const basePath = scriptUrl.pathname.substring(0, scriptUrl.pathname.lastIndexOf('/'));
  
  // 使用 fetch API 加载 HTML
  const response = await fetch(`${basePath}/panel.html`);
  const html = await response.text();
  
  // 手动注入 DOM
  document.body.insertAdjacentHTML('beforeend', html);
  
  // 初始化 Vue 应用
  createApp(App).use(pinia).mount('#phone-simulator-app');
}
```

**优势**:
- 不受插件文件夹命名影响
- 独立于 ST 内部实现
- 行为可预测

### 4.2 适配器与 Mock 服务

开发环境下使用 MockAdapter，生产环境使用 SillyTavernAdapter：

```typescript
// src/composables/useAdapter.ts
import { inject } from 'vue'
import type { HostAdapter } from '@/adapters/types'

export function useAdapter(): HostAdapter {
  const adapter = inject<HostAdapter>('host')
  if (!adapter) {
    throw new Error('HostAdapter not provided')
  }
  return adapter
}
```

**MockAdapter 功能**：
- 模拟 AI 消息接收
- 模拟 AI 生成响应
- 本地 Map 存储模拟持久化
- 测试辅助方法（`simulateAIMessage`）

### 4.3 暂存操作机制

用户操作不直接发送给 AI，而是暂存后批量提交：

```typescript
// stagedActionsStore.ts
const stagedActions = ref<StagedAction[]>([]);

function addAction(action: StagedAction) {
  stagedActions.value.push(action);
}

function formatForAI(): string {
  return stagedActions.value
    .map(a => `【${a.appName}】${a.description}`)
    .join('\n');
}

function commitToAI() {
  const formatted = formatForAI();
  TavernHelper.sendMessage(formatted);
  stagedActions.value = [];
}
```

|------|------|------|
| **通知服务** | `notification/` | 消息推送、优先级排序、勿扰过滤 |
| **音频服务** | `audioService.ts` | 音频播放、通道管理、焦点调度 |
| **时间服务** | `timeService.ts` | 时间源切换、模拟时间同步、定时任务 |
| **App 数据服务** | `appDataService.ts` | App 数据隔离存储 |
| **App 身份服务** | `appIdentityService.ts` | 应用身份验证、信任级别 |
| **提示词服务** | `promptService.ts` | 提示词模板管理 |
| **AI 生成服务** | `aiGenerateService.ts` | AI 内容生成封装 |

### 8.3 通知系统

通知系统采用 **State Injection** 模式，Service 接收 Store 的响应式引用：

```typescript
// Service 不直接依赖 Pinia，通过 init() 注入状态
class NotificationService {
  private _notifications: Ref<Notification[]> | null = null
  
  init(refs: { notifications: Ref<Notification[]> }) {
    this._notifications = refs.notifications
  }
  
  push(item: Notification) {
    this._notifications?.value.push(item)
  }
}
```

**优先级与抢占**：
| 优先级 | 权重 | 场景 | 行为 |
|--------|------|------|------|
| urgent | 4 | 来电、报警 | 打断低优先级，忽略部分 DND |
| high | 3 | 即时消息 | 打断普通通知 |
| normal | 2 | 应用推送 | 正常显示 |
| low | 1 | 后台同步 | 通常不显示 Toast |

详细文档参见 [通知系统](./systems/notification-system.md)

### 8.4 音频服务

音频服务管理不同类型的音频通道，支持独立音量控制和焦点调度：

| 通道 | 优先级 | 用途 | 行为 |
|------|--------|------|------|
| alarm | 5 | 闹钟 | 即使静音也播放 |
| ringtone | 4 | 来电 | 打断媒体 |
| notification | 3 | 通知 | 与媒体混音/压低 |
| system | 2 | 按键声 | 随触感设置 |
| media | 1 | 音乐/视频 | 被高优先级打断 |

详细文档参见 [音频服务](./systems/audio-service.md)

### 8.5 时间服务

支持多种时间源模式，适配角色扮演场景：

| 模式 | 描述 | 适用场景 |
|------|------|----------|
| System | 跟随系统时间 | 一般使用 |
| Simulated | 从聊天解析时间 | 跟随 RP 剧情 |
| Offset | 真实时间 + 偏移 | 模拟时区差异 |
| Virtual | 虚拟加速时间 | 时间加速剧情 |
| Frozen | 固定时刻 | 剧情定格 |

详细文档参见 [时间服务](./systems/time-service.md)

## 9. 应用商店与动态应用

### 9.1 应用类型

系统支持两类应用：**内置应用**和**动态应用**。

| 类型 | 技术 | 复杂度 | 适用场景 |
|------|------|--------|----------|
| 内置应用 | Vue 组件 | 高 | 复杂交互、系统功能 |
| 配置式应用 | JSON 配置 | 低 | 列表展示、简单工具 |
| 模板式应用 | JSON + 模板 | 中 | 自定义布局 |
| 组合式应用 | JSON + 预置组件 | 中高 | 多页面应用 |

### 9.2 应用身份识别

为解决同名应用冲突和数据安全问题，系统实现了分层信任模型：

```text
Level 0: 内置应用     → 编译时打包，完全信任
    ↓
Level 1: 官方仓库     → 仓库签名验证
    ↓
Level 2: 第三方仓库   → 用户添加信任，仓库签名
    ↓
Level 3: URL 导入     → 首次信任(TOFU)，警告用户
    ↓
Level 4: 本地文件     → 无法验证，强警告，完全隔离
```

**数据命名空间**：
| 来源 | 命名空间格式 | 示例 |
|------|--------------|------|
| 内置 | `builtin/{appId}` | `builtin/calculator` |
| 仓库 | `repo/{repoId}/{developerId}/{appId}` | `repo/official/calc-team/super-calc` |
| URL | `url/{domain}/{hash}` | `url/example.com/a1b2c3d4` |
| 本地 | `local/{installId}` | `local/inst_x7y8z9` |

详细设计参见 [App 身份识别设计](./dev/app-identity-design.md)

### 9.3 应用包格式

动态应用使用 `.phoneapp.json` 单文件格式：

```json
{
  "$schema": "https://phone-sim.app/schema/v1.json",
  "id": "com.example.notes",
  "name": "备忘录",
  "version": "1.0.0",
  "icon": {
    "type": "font",
    "value": "fas fa-sticky-note",
    "background": "#FFD60A"
  },
  "appType": "configurable",
  "permissions": ["storage", "ai-generate"],
  "dataVersion": 1
}
```

详细设计参见 [应用商店设计](./apps/app-store.md)
