**版本**: 2.2 (Vue3 重构版)

## 1. 概述

本项目使用 **Pinia** 作为状态管理库，采用模块化设计，将不同领域的状态分离到独立的 Store 中。

### 1.1 Store 架构

```
stores/
├── phoneStore.ts         # 主Store（聚合入口）
├── uiStore.ts            # UI状态（视图、位置、主题）
├── contactStore.ts       # 联系人管理
├── chatStore.ts          # 聊天消息管理
├── stagedActionsStore.ts # 暂存操作管理
└── appStateStore.ts      # App 状态管理（图标位置、运行状态）
```

### 1.2 状态持久化

使用 `pinia-plugin-persistedstate` 插件实现本地存储持久化：

```typescript
import { createPinia } from 'pinia';
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate';

const pinia = createPinia();
pinia.use(piniaPluginPersistedstate);
```

## 6. stagedActionsStore（暂存操作）

**文件**: `src/stores/stagedActionsStore.ts`

管理用户操作的暂存和提交。

### 6.1 核心概念

用户在手机界面上的操作（如发送消息、点赞）不会立即发送给 AI，而是先暂存起来，由用户决定何时批量提交。

### 6.2 状态

```typescript
interface StagedActionsStoreState {
  actions: StagedAction[];
}

interface StagedAction {
  id: string;
  timestamp: number;
  appName: string;
  actionType: string;
  target?: string;
  content?: string;
  description: string;
}
```

### 6.3 Getters

| Getter | 返回类型 | 说明 |
|--------|----------|------|
| `hasActions` | boolean | 是否有暂存操作 |
| `actionCount` | number | 暂存操作数量 |
| `formattedActions` | string | 格式化后的操作文本 |

### 6.4 Actions

| Action | 参数 | 说明 |
|--------|------|------|
| `addAction(action)` | action: Omit | 添加操作 |
| `removeAction(id)` | id: string | 移除操作 |
| `clearActions()` | - | 清空所有操作 |
| `formatForAI()` | - | 格式化为 AI 可读文本 |
| `commitToAI()` | - | 提交到 AI |

### 6.5 操作类型

| 类型 | 应用 | 示例 |
|------|------|------|
| send_message | 微信 | 向xxx发送消息："内容" |
| send_voice | 微信 | 向xxx发送语音消息 |
| send_image | 微信 | 向xxx发送图片 |
| send_redpacket | 微信 | 向xxx发送红包：100元 |
| send_email | 邮件 | 发送邮件给xxx |

### 6.6 格式化输出

```typescript
function formatForAI(): string {
  return actions.value.map(action => {
    return `【${action.appName}】${action.description}`;
  }).join('\n');
}
```

**输出示例**:
```
【微信】向小明发送消息："今晚有空吗？"
【微信】向小明发送红包：66元，祝福语"生日快乐"
```

### 6.7 使用示例

```typescript
import { useStagedActionsStore } from '@/stores/stagedActionsStore';

const stagedStore = useStagedActionsStore();

function sendMessage(contactId: string, content: string) {
  const contact = contactStore.getContact(contactId);
  
  stagedStore.addAction({
    appName: '微信',
    actionType: 'send_message',
    target: contact.name,
    content,
    description: `向${contact.name}发送消息："${content}"`,
  });
}

function commitAll() {
  stagedStore.commitToAI();
}
```

## 9. 路由状态

### 9.1 概述

除了 Pinia Store 外，项目还在 `src/router/index.ts` 中维护了一些响应式路由状态，供手势系统和动画系统使用。

### 9.2 导出的响应式状态

```typescript
// src/router/index.ts
import { ref, computed } from 'vue'

// 导航方向
export const navigationDirection = ref<'forward' | 'back'>('forward')

// 导航历史栈（响应式）
const historyStack = ref<string[]>(['/'])

// 是否可以返回（基于内部历史栈判断）
export const canGoBack = computed(() => {
  return historyStack.value.length > 1
})

// 缓存组件列表
export const cachedComponents: string[] = [
  'HomeScreen', 'ChatApp', 'SettingsApp',
  'EmailApp', 'BrowserApp', 'LiveCenterApp'
]
```

### 9.3 状态说明

| 状态 | 类型 | 说明 |
|------|------|------|
| `navigationDirection` | `Ref<'forward' \| 'back'>` | 当前导航方向，用于动画选择 |
| `historyStack` | `Ref<string[]>` | 内部历史栈，追踪导航路径 |
| `canGoBack` | `ComputedRef<boolean>` | 是否可以返回，供手势系统判断 |
| `cachedComponents` | `string[]` | 需要 KeepAlive 缓存的组件名列表 |

### 9.4 为什么不使用 window.history？

项目使用 Vue Router 的 **Memory History** 模式，不会修改浏览器的 `window.history`。因此：

- `window.history.length` 不会因应用内导航而改变
- 必须维护内部历史栈来追踪导航历史
- `canGoBack` 基于内部历史栈判断，而非 `window.history`

### 9.5 使用示例

```typescript
// ViewsContainer.vue 中使用
import { canGoBack as routerCanGoBack, navigationDirection } from '@/router'

// 手势处理中检查是否可以返回
if (canGoBack.value) {
  router.back()
}

// 动画方向
const transitionName = computed(() => {
  return navigationDirection.value === 'back' ? 'slide-back' : 'slide'
})
```

## 10. appStateStore（App 状态）

**文件**: `src/stores/appStateStore.ts`

管理每个 App 的运行时状态，主要用于支持 zoom 动画和未来的多任务切换功能。

```typescript

  /** App 图标在桌面上的位置 */
```

### 10.5 使用场景

**1. HomeScreen 挂载时注册所有图标位置**：
```typescript
// HomeScreen.vue
import { useAppStateStore, getAppIdFromRoute } from '@/stores/appStateStore'

const appStateStore = useAppStateStore()

onMounted(() => {
  nextTick(() => {
    // 遍历所有图标 DOM 元素，注册位置
    iconRefs.value.forEach(({ appId, element }) => {
      appStateStore.registerIconFromElement(appId, element, containerRef.value)
    })
  })

```

**2. 打开 App 时使用图标位置作为动画起点**：
```typescript
function openApp(app: AppItem, event: MouseEvent | TouchEvent) {
  const appId = getAppIdFromRoute(app.route)
  const iconPosition = appStateStore.getIconPosition(appId)
  
  if (iconPosition) {
    setZoomOrigin(iconPosition)
  }
  
  router.push(app.route)
}
```

**3. ViewsContainer 监听路由变化，设置动画终点**：
```typescript
// ViewsContainer.vue
watch(
  () => route.path,
  (newPath, oldPath) => {
    if (transitionType.value !== 'zoom') return
    
    // 返回桌面时，使用当前 App 的图标位置作为缩小终点
    if (newPath === '/' && oldPath && oldPath !== '/') {
      const appId = getAppIdFromRoute(oldPath)
      const iconPosition = appStateStore.getIconPosition(appId)
      
      if (iconPosition) {
        setZoomOrigin(iconPosition)
      }
    }
  }
)
```

### 10.7 设计理念

- **页面应用化**：每个 App 的状态独立管理，类似移动端原生应用
- **动画支持**：记录图标位置用于 zoom 动画的精确定位
- **多任务切换**：`lastRoute` 和 `isRunning` 支持多任务切换功能
- **统一管理**：App 运行状态、切换器可见性都由 appStateStore 集中管理

## 11. deviceStore 导航模式

### 11.1 导航模式状态

deviceStore 除了管理设备模式（phone/tablet/desktop），还管理导航模式：

```typescript
// src/stores/deviceStore.ts
type NavigationMode = 'gesture' | 'buttons'

const navigationMode = ref<NavigationMode>('gesture')

// 是否为手势导航模式
const isGestureNavigation = computed(() => navigationMode.value === 'gesture')

// 切换导航模式
function setNavigationMode(mode: NavigationMode) {
  navigationMode.value = mode
}

// 切换导航模式
function toggleNavigationMode() {
  navigationMode.value = navigationMode.value === 'gesture' ? 'buttons' : 'gesture'
}
```

### 11.2 导航模式说明

| 模式 | 值 | 特点 |
|------|-----|------|
| 手势导航 | `'gesture'` | iOS 风格，底部上滑返回桌面/多任务，边缘滑动返回 |
| 三键导航 | `'buttons'` | Android 风格，底部显示返回/主页/多任务三个按键 |

### 11.3 使用示例

```typescript
import { useDeviceStore } from '@/stores/deviceStore'

const deviceStore = useDeviceStore()

// 检查当前导航模式
if (deviceStore.isGestureNavigation) {
  // 手势导航模式下的逻辑
}

// 切换到三键导航
deviceStore.setNavigationMode('buttons')

// 切换导航模式
deviceStore.toggleNavigationMode()
```

### 11.4 与其他组件的交互

- **ViewsContainer.vue**：根据 `isGestureNavigation` 决定是否处理底部上滑手势
- **NavigationBar.vue**：仅在 `!isGestureNavigation` 时显示
- **SettingsApp.vue**：提供导航模式切换开关

|------|------|------|
| `setZoomOrigin(origin)` | ZoomOrigin | 设置 zoom 动画的原点位置 |
| `setZoomOriginFromEvent(event, container?)` | MouseEvent/TouchEvent, HTMLElement? | 根据点击事件计算 zoom 原点 |
| `resetZoomOrigin()` | - | 重置 zoom 原点到中心 (50%, 50%) |
| `setTransitionType(type)` | 'slide' \| 'zoom' | 手动设置过渡类型 |

### 12.3 路由守卫中的自动判断

```typescript
router.beforeEach((to, from, next) => {
  const toPath = to.path
  const fromPath = from.path
  
  // 桌面 → App：使用 zoom 动画
  if (fromPath === '/' && toPath !== '/') {
    transitionType.value = 'zoom'
    navigationDirection.value = 'forward'
    // ...
  }
  
  // App → 桌面：使用 zoom 动画
  if (toPath === '/' && fromPath !== '/') {
    transitionType.value = 'zoom'
    navigationDirection.value = 'back'
    // ...
  }
  
  // 其他情况：使用 slide 动画
  transitionType.value = 'slide'
  // ...
})
```
